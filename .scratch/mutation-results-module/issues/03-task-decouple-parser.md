## Question

After the model is settled, how do we decouple the parsing logic from the Gradle `MutationResultsTask` class so it's a pure, testable function?

### Current state

`parseMutflowSummary(stdout: String): List<Map<String, Any?>>` is a private method on `MutationResultsTask` (lines 168–222). It depends on nothing Gradle-specific (uses `java.util.regex.Pattern`, `java.io.File`); it's just co-located in the Gradle task class, which makes it impossible to unit-test without instantiating a Gradle `Project`.

### Required change

Extract the parsing into a standalone Kotlin file/module:
- `parseMutflowSummary(stdout: String): List<MutationResult>` — pure function, no Gradle imports
- `calculateMetrics(mutations: List<MutationResult>): MutationStats` — pure function returning score, band, confidence, totals
- `buildTestKillerMatrix(mutations: List<MutationResult>): Map<String, List<String>>` — pure function
- `serializeToJson(results: MutationResults): String` — kotlinx.serialization output

The `MutationResultsTask.generateResults()` method becomes a thin adapter: collect JUnit XML files → call pure functions → write JSON to output file.

The exact file layout and module name (e.g. `.omp/mutation-results-src/`) depends on the answer to ticket 01.

## Answer

**Resolved**: The typed module is in `.omp/mutation-results-src/main/kotlin/io/omp/mutation/`:
- `MutationResult.kt` — `@Serializable data class` with 6 fields
- `MutationResults.kt` — top-level `MutationResults`, enums, and `MutationStats`
- `MutationResultsParser.kt` — `parseMutflowSummary`, `calculateMetrics`, `buildTestKillerMatrix`, `assembleResults` as pure functions in an `object`
- `MutationResultsSerializer.kt` — `toJson(results)` using kotlinx.serialization

The `MutationResultsTask` in `.omp/mutation-results.gradle.kts` is now a thin adapter: collects JUnit XML → calls pure functions → writes JSON. The script imports from buildSrc, which is generated by the bootstrap (see ticket 05).

Verified: 17 unit tests pass in buildSrc; `gradle mutationResults` in the sample project produces correct JSON with 31/31 killed, 100% score, Excellent band, Medium confidence.
